## Detailed Telemetry and Output Metrics

Because this framework functions as a high-fidelity Digital Twin, it generates extensive telemetry across the physical, MAC, and transport layers. Below is a detailed explanation of the output files generated in the root directory after a successful simulation run:

### 1. End-to-End Flow Statistics (ns-3 FlowMonitor)
These JSON files are generated natively by the ns-3 FlowMonitor module at the end of the simulation. They contain the final application-layer statistics for the cyber-physical evaluation.
*   `digital_twin_flowmon_udp.json`: Contains the baseline metrics for the UDP stress test. You can parse this file to extract the Packet Loss Ratio ($\approx 7.7\%$), average Throughput ($\approx 39.68 \text{ Mbps}$), Mean Delay, and Jitter.
*   `digital_twin_flowmon_tcp.json`: Contains the equivalent flow metrics when the framework is executed using the TCP transport protocol.
*   `expA_replication_flowmon_tcp.json` / `expB_counterfactual_flowmon_tcp.json`: Specific flow outputs generated when toggling the `--enableXapp` command-line argument to compare the baseline (stationary) network against the proactive (mobile) network.

### 2. 5G-LENA Physical and MAC Layer Traces
These text files are generated by the 5G-LENA module and the custom `MlPropagationLossModel`. They track the precise radio frequency physics and queueing mechanics at a per-packet resolution.
*   `DlDataSinr.txt` / `DlCtrlSinr.txt`: Logs the Downlink Signal-to-Interference-plus-Noise Ratio (SINR). The C++ engine actively reads `DlDataSinr.txt` during the simulation to export live RF metrics to the terminal.
*   `DlPathlossTrace.txt`: Records the combined pathloss applied to the channel, including both the foundational 3GPP distance-based attenuation and the sudden dynamic penalties injected by the Machine Learning (ML) model during line-of-sight blockages.
*   `NrDlMacStats.txt`: Tracks the MAC layer scheduling. This is critical for observing how the network dynamically adapts its Modulation and Coding Scheme (MCS) during a geometric blockage.
*   `NrDlRlcStatsE2E.txt`: Logs the Radio Link Control (RLC) layer buffer statistics. This file verifies the strict 1.5 MB tail-drop buffer limitation and captures the "buffer flush" throughput impulses (up to $\approx 150 \text{ Mbps}$) that occur immediately after line-of-sight is restored.
*   `RxPacketTrace.txt`: Records the exact reception timestamps for every packet, used for microscopic delay and jitter analysis.

### 3. Transport Protocol Metrics (TCP Kinematic Jitter Analysis)
These CSV files isolate the cross-layer vulnerability defined in the thesis as "Kinematic Jitter"—where the physical movement of the robotic base station causes TCP to artificially collapse its transmission window.
*   `tcp_cwnd.csv` / `baseline_tcp_cwnd.csv`: Logs the TCP Congestion Window size over time. By comparing the dynamic xApp execution against the baseline, you can visualize how continuous robotic movement tricks TCP into detecting network congestion.
*   `tcp_rtt.csv` / `baseline_tcp_rtt.csv`: Logs the Round Trip Time (RTT) fluctuations induced by mobility and MAC-layer MCS adaptations.
*   `5g-traffic-*.pcap`: Raw packet capture files generated during the simulation. These can be opened in Wireshark for deep packet inspection of the TCP acknowledgement (ACK) variations.

## Python Analysis and Visualization Scripts

The repository includes several custom Python scripts designed to parse the raw ns-3 trace files and generate the comparative validation graphs (matching the figures presented in Chapter 4 of the thesis). 

*   `validate_twin.py` & `plot_validation.py`: These scripts chronologically synchronize the empirical ground-truth dataset (`Cleaned_Trace.csv`) with the simulation output. They generate the 2D spatial trajectory maps showing the exact overlap between the physical testbed movements and the virtual entities, validating the spatial ingestion engine.
*   `tcp-compare.py` & `tcp_plot_new.py`: These scripts parse the FlowMonitor JSONs and the `tcp_cwnd.csv` traces to plot UDP versus TCP performance side-by-side. They are responsible for generating the graphs that highlight the TCP "Congestion Collapse" caused by Kinematic Jitter.
*   `plot_snr.py` & `comparison.py`: These scripts visualize the physical-layer fidelity. They plot the moment the simulated robotic base station hits its physical speed limit ($1.5 \text{ m/s}$), showing the subsequent geometric collision, the immediate application of the ML signal penalty, and the resulting drop in application throughput.
